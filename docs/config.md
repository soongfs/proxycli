# Config Module

`proxycli.config` owns Jinja2 template loading, rendering, writing, and reading
for sing-box JSON configuration.

## Template Variables

The packaged template receives two variables:

- `nodes`: list of sing-box outbound dictionaries generated by the parser.
- `node_tags`: list of node tags extracted from `nodes`.

The template uses Jinja2 `tojson` for both values so generated JSON remains
valid even when tags or node fields contain quotes or non-ASCII text.

## Config Structure

Generated configs include:

- log level `info`
- DNS servers for local DNS, remote TLS DNS, and fakeip
- TUN inbound with `auto_route`, `auto_redirect`, `strict_route`, and
  `stack: system`
- mixed HTTP/SOCKS inbound on `127.0.0.1:7890`
- selector outbound tagged `proxy`
- all parsed node outbounds
- direct outbound tagged `direct`
- route rules that send `geoip-cn` and `geosite-cn` traffic to direct
- final route to the `proxy` selector

## Validation

`generate_config` renders the template and immediately parses the result with
`json.loads`. It writes normalized, indented JSON only after that validation
succeeds.

## Default Paths

The default config path is `~/.config/proxycli/config.json`. Parent directories
are created automatically when writing.

## Sing-box Validation

The module does not shell out to `sing-box check` because tests and config
generation should be usable before sing-box is installed. A future CLI command
can add optional external validation.
